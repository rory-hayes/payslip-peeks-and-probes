## Claims Implemented
- Public landing, guides, calculators, legal pages, and pricing exist.
- Auth, onboarding, dashboard, vault, upload, extraction, anomaly, draft, settings, and checkout pages exist.
- Supabase migrations define core user-owned data tables and storage policies.
- Tests exist for a small subset of draft creation, checkout return polling, account deletion ordering, and a placeholder example.

## Claims Not Implemented Or Not Verified
- End-to-end signup, upload, extraction, anomaly, billing, and deletion flows were not verified against a live Supabase backend.
- US payslip support is claimed in UI but not aligned in database constraints or extraction schema.
- Live payments were not verified.
- Production deployment provider and CI are not configured in repo.
- Analytics provider is not wired.

## Contradictions Between Handoff-Like Content And Code
- Brand/domain mismatch: UI says `PayCheck`, metadata and sitemap say `Payslip Insights`, comments mention `paycheckinsights.com`, and public files use `payslipinsights.com`.
- Country support mismatch: marketing and calculators include US, but migrations constrain `profiles.country` to non-US countries and the main extraction prompt does not output US.
- README previously claimed nothing useful beyond Lovable placeholder text.

## Recommended Next Actions
- Treat `ROADMAP.md` as the new source of truth.
- Resolve P0 security, lint, dependency, country-scope, and deployment gaps before feature expansion.
- Decide whether to preserve Lovable gateways or replace them with first-party OpenAI/Stripe integrations.
