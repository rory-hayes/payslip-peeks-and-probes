## Executive summary

The current local web release candidate renders and passes its automated
baseline. The public marketing routes and the read-only demo were exercised in
desktop and mobile-sized Chromium sessions without a confirmed local UI,
console, or request failure.

The product is not ready to accept real customers or call itself production
live. The public domain serves a stale anonymous deployment, the paid release
preflight is intentionally blocked by unfinished legal/provider disclosures,
the linked Supabase project could not be inspected with the available account,
and the Expo companion has four remaining high-severity upstream build-chain
audit findings. These are release and operations blockers, not evidence that
the local product flow is broken.

A read-only security scan of the audited commit found one medium and two low
source-backed issues: native bearer-token handling over the custom scheme, a
cross-account payslip UUID existence oracle, and missing anti-clickjacking
headers. The current worktree fixes all three; focused mobile tests, root
verification, and static header assertions pass. The generated scan report is
linked from the handoff rather than treating the original findings as proof
that the patched worktree is vulnerable.

## Findings

### BUG-001 — Public domain serves stale release

- Severity: Release blocker
- Status: Confirmed external deployment mismatch
- Evidence: `curl` returned HTTP 200 from `https://payslipinsights.com/`,
  but the response contained the older Lovable-marked page; the same host
  returned `404 Not Found` for `/release.json`. The local candidate emits a
  release manifest, so the public host is not serving this reviewed source.
- Impact: Visitors and any future customer traffic would see an older
  product, and the live revision cannot be verified.
- Next action: Select the production host, publish the exact clean web
  revision, then run `npm run release:web:verify-public` against the resulting
  URL before pointing the custom domain at it.

### BUG-002 — Paid release preflight is blocked by owner-controlled facts

- Severity: Release blocker
- Status: Confirmed intentional gate
- Evidence: `npm run release:web:preflight` exits non-zero because the Privacy
  Policy still needs the provider, retention, analytics, and cookie disclosures,
  while the Terms still need the operating entity, contact, and governing-law
  details.
- Impact: Publishing a paid flow now would require inventing legal or data
  handling claims.
- Next action: Supply and review the real entity/contact/governing-law,
  provider/DPA/retention, and cookie/analytics facts; then rerun the paid
  preflight from a clean release worktree.

### BUG-003 — Linked Supabase project is not verifiable with current access

- Severity: Release blocker
- Status: Confirmed external access blocker
- Evidence: `npx supabase migration list --linked --project-ref
  shvivlhawhczbljzhvmr` and `npx supabase functions list --project-ref
  shvivlhawhczbljzhvmr` both returned HTTP 403, “account does not have
  necessary privileges.” Safe public settings and an empty profiles query were
  reachable, but that does not prove migrations, functions, secrets, schedules,
  or tenant isolation.
- Impact: The current source cannot be claimed to match the backend that would
  process a real payslip or payment.
- Next action: Run the staged migration/function, secret, schedule, two-account,
  provider, and Stripe checks with an account that owns the target project.

### BUG-004 — Mobile dependency audit has unresolved upstream findings

- Severity: Native release blocker
- Status: Confirmed upstream dependency gate
- Evidence: After the compatible audit fix, `npm audit --omit=dev` in
  `apps/mobile` still reports four high findings through the Metro/image-size
  chain pulled by React Native 0.86.2. The local typecheck, tests, Expo config,
  and web export still pass (31 mobile tests after the security remediation).
- Impact: The companion should not be shipped as a signed native binary until
  the compatible Expo/React Native train resolves the chain or an approved
  vendor remediation is available.
- Next action: Track the upstream compatible release, update the Expo train,
  rerun audit and mobile verification, then produce and install a signed
  release-device build.
